# PRレビュー⇄レビュー対応 自動ラリースキル (pr-review-rally) 【試作段階】

## 🎯 背景・目的

通常、PRのレビューとその対応は「レビュースキルを起動 → 出た指摘にpr-review-respondスキルで対応 → 直すと新たな観点の指摘が出ることがあるので再度レビュー → また対応 …」という往復（ラリー）になる。これまではこの往復のたびにユーザーが手動でスキルを起動し直す必要があった。本スキルは、この往復を人間の都度の起動なしに自動で回すためのオーケストレーションスキルである。

## 🎯 起動条件

- ユーザーから「PRのレビューとレビュー対応を自動でラリーして」「レビューと対応を繰り返して」等、本スキルの実行を明示的に指示された場合。
- 対象PRが未指定の場合はユーザーに確認する。

## 📐 ラウンド構成（なぜラウンドごとに手段が違うか）

- **上限は3ラウンド。** レビューは軽微な指摘を毎回言い回しを変えて出し続けることがあり、上限を設けないと収束しない自律ループになりうる。3ラウンドを超えて指摘が残る場合は自動継続せず、必ずユーザーへ判断を委ねる。
- **1ラウンド目**: `multi-agent-review`スキル（5観点を1エージェントが順番に切り替えて厳格にレビューするもの）と、標準の`review`スキルの**両方**を実行する。初回は最も網羅的に指摘を洗い出したいため。
- **2・3ラウンド目**: 標準の`review`スキルのみを実行する。`multi-agent-review`は差分規模に比例してトークン消費が大きいため、2巡目以降まで毎回実行するとコストが線形に積み上がる。1ラウンド目で厳格な5観点チェックは既に一巡しているため、2巡目以降は軽量な`review`スキルで新たに生じた問題（前ラウンドの修正自体が生んだ問題等）を追いかければ十分と判断した。

## 🏷️ 「レビュー完了」マーカーコメント

ラリーが**収束して完了した**（＝いずれかのラウンドで新規指摘が0件になった）場合にのみ、本スキルは対象PRへ以下の内容を`add_issue_comment`で投稿する。このコメントが「このPRは本スキルによるレビューラリーが完了済み」であることの目印（マーカー）になる。

```
## ✅ pr-review-rally: レビュー完了

<!-- pr-review-rally:completed -->

ラウンド{収束したラウンド番号}で新規の指摘が0件になったため、レビューラリーを完了としました。

- ラウンド1: multi-agent-review + review、指摘{件数}件、対応コミット{件数}件
- ラウンド2: review、指摘{件数}件、対応コミット{件数}件
...(実施したラウンド分)
```

- `<!-- pr-review-rally:completed -->`という固定のHTMLコメント文字列を**必ず本文に含める**こと。次回以降の起動時にこの文字列の有無で完了済みかどうかを判定するため、文言・大文字小文字を変えてはならない。
- **3ラウンド上限に到達して打ち切った場合はこのマーカーを投稿しない**（指摘が残っている可能性がある不完全終了のため。マーカーを付けると次回以降ずっとキャンセルされ再ラリーできなくなってしまう）。この場合は後述の「3. 完了報告」に従い、マーカーを含まない通常のPRコメントで打ち切りの旨を報告する。

## 📋 実行プロセス（手順）

### 1. 対象PRの特定・事前チェック

1. ユーザー指定のPR URL・番号から対象を特定する。`pull_request_read`（method: `get`）でブランチ・状態を確認する。
2. **完了マーカーの確認**: `pull_request_read`（method: `get_comments`）でPRの通常コメント一覧を取得し、本文に`<!-- pr-review-rally:completed -->`を含むコメントが既に存在するか確認する。
   - **存在する場合**: このPRは既に本スキルによるレビューラリーが完了済みと判断し、**新たなレビュー・レビュー対応は一切実行せず、その旨をユーザーへ報告してスキルの実行を中断（キャンセル）する**。再度レビューさせたい場合は、当該マーカーコメントをGitHub上で削除するか、ユーザーが明示的に「マーカーを無視して再実行して」等と指示する必要がある旨を案内する。
   - **存在しない場合**: 手順3へ進む。
3. **既存の未解決レビュースレッドの確認**: `pull_request_read`（method: `get_review_comments`）で全レビュースレッドを取得し、`is_resolved: false`のスレッドが無いか確認する。
   - **未解決スレッドがある場合**: これは人間のレビュアーや別セッションが残した、まだ対応されていない指摘とみなす。通常のラウンド1（`multi-agent-review`＋`review`）を実行する**前に**、まず`pr-review-respond`スキルを自律モードで起動し、これらの既存スレッド全てへ対応・コミット・返信・pushさせる。この対応は「ラウンド0」（前処理）として扱い、後述のラウンド1〜3のカウントには含めない（上限3ラウンドの実質的な目減りを防ぐため）。
   - **未解決スレッドが無い場合**: そのまま手順2（ラウンドループ）へ進む。

### 2. ラウンドループ（最大3回、収束したら早期終了）

各ラウンドで以下を行う。

1. **このラウンドで使うレビュー手段を決定する**（1ラウンド目: 両方、2・3ラウンド目: `review`のみ、上記「ラウンド構成」参照）。
2. **`multi-agent-review`を使う場合**（1ラウンド目のみ）: `Skill`ツールで`multi-agent-review`を対象PRに対して起動する。このスキル自体が指摘をPRへインラインレビューコメントとして投稿するところまで行う（詳細は[multi-agent-reviewのSKILL.md](../multi-agent-review/SKILL.md)参照）。
3. **`review`を使う場合**（全ラウンド共通）: `Skill`ツールで`review`を対象PRに対して起動する。標準の`review`スキルはチャットへのテキスト出力のみでPRには投稿しないため、その出力（具体的な指摘・改善提案・懸念事項）を、自分自身で以下の手順によりPRへインラインレビューコメントとして投稿する（`multi-agent-review`の投稿手順に準拠）。
   1. `pull_request_review_write`（method: `create`）でペンディングレビューを作成する。
   2. 指摘ごとに`add_comment_to_pending_review`を呼ぶ。`path`/`line`（`side`: `RIGHT`、`subjectType`: `LINE`）を指摘対象のfile:lineに合わせる。`body`の先頭に`[general-review]`を付与し、指摘の要約・根拠・具体的な不具合シナリオを含める。
   3. 特定のfile:lineに紐づかない全体的な指摘（概要コメント等）は、`add_issue_comment`で通常のPRコメントとして投稿する。
   4. 全指摘を追加し終えたら`pull_request_review_write`（method: `submit_pending`、`event`: `COMMENT`）で送信する。指摘が0件の場合はペンディングレビューを作らず、その旨を記録するだけでよい。
4. **このラウンドで新たに投稿したインラインコメント・PRコメントの件数を数える。**
   - **0件の場合**: このラウンドで収束したと判断し、ループを抜けて手順3（完了報告）へ進む。
   - **1件以上の場合**: `pr-review-respond`スキルを**自律モードとして**（Y/N確認を省略して）起動し、このラウンドで投稿された指摘全てに対応・コミット・返信させる。検証（テスト・lint・型チェック等）は自律モードでも必ず全て実行し成功させること（省略しない）。対応完了後、pr-review-respondスキル自身の手順に従いこのラウンド内でpushまで行う。
5. 次のラウンドへ進む。**次ラウンドのレビューは必ず最新のdiff（前ラウンドの修正コミットを含む）に対して行う**こと。前ラウンドの差分をキャッシュして使い回さない。

### 3. 完了報告

- **「新規指摘0件で収束」の場合**: 上記「🏷️ 「レビュー完了」マーカーコメント」の内容でPRへ`add_issue_comment`を投稿する（`<!-- pr-review-rally:completed -->`を必ず含める）。あわせてチャット上にも、各ラウンドで実施したレビュー手段・投稿した指摘件数・対応コミット数を簡潔に一覧化して報告する。
- **「3ラウンド上限に到達して打ち切り」の場合**: 完了マーカーは投稿しない。代わりに、マーカー文字列を含まない通常のPRコメントで「3ラウンド上限に到達したため自動ラリーを打ち切りました。残存指摘の有無をご確認ください」という趣旨を投稿する。チャット上には、最後のラウンドで残っていた（対応済みの）指摘一覧と、まだ懸念が残っていそうな点を提示し、追加のラリーが必要かどうかの判断をユーザーに委ねる。
- **手順1でキャンセルした場合**: 上記いずれのPRコメントも投稿せず、キャンセルした旨（完了マーカーが既に存在していたこと）のみをチャットでユーザーへ報告する。

## 🚫 制約・注意点

- 本スキルは`pr-review-respond`スキルを内部的に複数回、自律モードとして呼び出す。AGENTS.md記載のpr-review-respond自律モードのルール（1コメント=1コミット、auto-commit経由でのコミット、検証省略禁止）はラウンドごとにそのまま適用される。
- **force push（`--force`/`-f`）はいかなる場合も絶対に禁止。** 通常のpushのみ許可される（branch_rules.md参照）。
- `multi-agent-review`は【試作段階】のスキルであり、その既知の限界（観点間のアンカリング等、[multi-agent-reviewのSKILL.md](../multi-agent-review/SKILL.md)参照）が1ラウンド目の指摘にもそのまま及ぶ。
- 3ラウンドを超えて指摘が残っていても、4ラウンド目以降を自動で継続してはならない。必ずユーザーへ報告し判断を仰ぐ。
- 完了マーカー（`<!-- pr-review-rally:completed -->`）は「新規指摘0件での収束」の証跡として機能する。ラウンド0（既存未解決スレッドへの前処理）や3ラウンド上限到達での打ち切りなど、収束以外の終了パターンでは絶対に投稿しないこと。誤って投稿すると、実際には指摘が残っているPRが「レビュー完了済み」と誤認され、以降の起動が全てキャンセルされてしまう。
